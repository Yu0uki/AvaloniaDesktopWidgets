###### Visual Tree 冲突修复

**问题发现**:
```
进入插件页面 → 返回主页面 → 再次点击插件 → 崩溃
System.InvalidOperationException: 
The control already has a visual parent
```

**根本原因**:
1. 插件端缓存了视图实例
2. 宿主端未清除 CurrentPage

**解决方案**:

**修复 1**: 插件每次创建新实例
```csharp
public Control GetMainView()
{
    // 每次都创建新实例，避免 Visual Tree 冲突
    return new WorldClockView();
}
```

**修复 2**: 返回时先清除 CurrentPage
```csharp
private void NavigateBackToDashboard()
{
    // 先清除 CurrentPage，让 Avalonia 从 Visual Tree 中移除插件视图
    CurrentPage = null;
    
    IsShowingPluginView = false;
    CurrentPluginName = "";
    SelectedPluginId = null;
    StatusMessage = "";
    
    // 然后设置新的页面
    NavigateToDashboard();
}
```

**测试验证**:
- 重复打开/关闭插件 10 次以上
- 无崩溃、无异常

**文件变更**:
- 修改: `Plugins/WorldClockPlugin/WorldClockPlugin.cs` (-20行)
- 修改: `AvaloniaApplication2/ViewModels/MainWindowViewModel.cs` (+6行)

**经验总结**:
- Avalonia 控件只能有一个 Parent
- 不要缓存视图实例
- 导航时显式清除旧视图

## 🎯 关键技术决策

### 1. 为什么选择 Microsoft.Extensions.DependencyInjection？

**考虑因素**:
- 官方维护，稳定性高
- 与 .NET 生态系统无缝集成
- 学习成本低，文档完善
- 性能优秀

**替代方案**:
- Autofac：功能更强大，但学习曲线陡峭
- Unity：微软已停止维护
- SimpleInjector：轻量级，但生态较小

**决策**: 选择 Microsoft 官方方案，平衡功能和复杂度

---

### 2. 为什么使用 Serilog 而非内置日志？

**考虑因素**:
- 结构化日志，便于查询和分析
- 丰富的 Sink 生态系统
- 灵活的配置选项
- 性能优秀

**对比**:
- `ILogger`：简单但功能有限
- NLog：功能类似，但 Serilog 更现代化
- log4net：老牌但配置复杂

**决策**: Serilog 的结构化日志更适合现代应用

---

### 3. 为什么实现插件热重载？

**业务价值**:
- 插件开发效率提升 10 倍+
- 无需重启应用即可测试
- 实时反馈，加速迭代

**技术挑战**:
- 文件锁定检测
- 资源释放时序
- 防抖机制

**决策**: 虽然增加了复杂度，但显著提升开发体验，值得投入

---

### 4. 为什么插件不缓存视图实例？

**问题背景**:
- 缓存导致 Visual Tree 冲突
- Avalonia 控件只能有一个 Parent

**解决方案**:
- 每次调用 `GetMainView()` 返回新实例
- 宿主端导航时先清除 `CurrentPage = null`

**性能影响**:
- 视图创建开销很小（毫秒级）
- 垃圾回收会自动清理旧实例
- 避免了复杂的生命周期管理

**决策**: 简单有效的方案，优于复杂的缓存策略

### 遇到的坑

#### 1. Avalonia Visual Tree 约束

**问题**: 控件不能同时属于多个 Parent

**教训**:
- 理解框架的核心约束
- 不要假设 WPF 的经验完全适用
- 遇到异常时查阅官方文档

**解决**: 每次创建新实例，导航时清除旧视图

---

#### 2. FileSystemWatcher 的陷阱

**问题**:
- 文件写入过程中会多次触发事件
- 文件可能被其他进程锁定

**教训**:
- 必须实现防抖机制
- 检查文件可访问性
- 适当的延迟等待

**解决**: 500ms 防抖 + 文件锁定检测 + 1秒等待

---

#### 3. 测试隔离的重要性

**问题**: 测试之间相互影响，导致随机失败

**教训**:
- 每个测试使用独立的环境
- 测试后清理资源
- 避免共享状态

**解决**: 临时目录 + Dispose 模式
